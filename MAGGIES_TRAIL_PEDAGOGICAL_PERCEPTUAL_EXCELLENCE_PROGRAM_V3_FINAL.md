1. Executive decision
The attached program is the right target state, but it must not be executed as if the repository were starting from zero.
Maggie's Trail already has unusually strong instructional machinery, a broad K–calculus corpus, complete runtime variant coverage, a large manipulative library, a working core math-rendering boundary, and substantial historical QA. The next program must preserve those assets while correcting four strategic gaps:
Coverage is being mistaken for quality. All 4,471 practice-eligible steps have runtime variants, but the repository does not yet prove that all 434 generators remain mathematically, linguistically, visually, and pedagogically excellent across representative seeds.
Rendering is being mistaken for semantic mathematics. The current shorthand-to-KaTeX boundary is useful, but the V3 target requires structured mathematical state, canonicalization, and runtime proof across generated values—not only recognition of authored strings.
Historical task records have drifted. Several plans still say “scoping only” after work shipped, and the 11,487-row pending queue contains counts that were superseded by later closure work. A new evidence baseline must precede mass edits.
Instructional strength is ahead of product readiness. A first-run Grade 3 onboarding branch can dead-end, the current dependency audit has one high-severity transitive finding, and billing, email delivery, durable hosted sync, LTI delivery, observability, deployment, and independent efficacy evidence remain incomplete.
The updated strategy is therefore:
Refresh truth once, establish structural invariants, prove them on a gold cohort, then scale root-cause repairs by concept family and generator reach.

Create /.cowork-cache/pedagogy-v3/ as an unshipped, reproducible worker cache.
Required cache layers
Snapshot manifest — corpus hash, source-file hashes, dependency lock hash, runtime versions, extractor versions, exclusions, generation time.
Repository graph — repo map, import graph, hot-file map, test map.
Curriculum graph — course, lesson, step, concept, prerequisite, remedial, challenge, and progression indexes.
Generator graph — generator inventory, user map, variant-family map, parameter-space/risk metadata, seed/sample manifest.
Quality indexes — duplicates, raw math, canonical form, symbolic display, fractions, constants, derivatives, integrals, units, decimal/fraction policy, machine-expression leaks, language, figures, engines, visual support, misconceptions, and state synchronization.
Task packets — immutable input manifests, decisions, allowed files, tests, expected evidence, and stop rules.
Invalidation rules
Use content hashes, not timestamps.
A lesson edit invalidates only its lesson/step/question/duplicate/presentation records and affected task packets.
A generator edit invalidates its user map, all sampled outputs, duplicate/language/math/visual/state-sync audits, and downstream family packets.
A renderer/canonicalizer/schema edit invalidates every runtime math fixture and presentation certification.
A visual primitive edit invalidates all placements and screenshot fixtures that depend on it.
Cache outputs are evidence accelerators, never source-of-truth curriculum and never included in release archives.
Precache performance policy
Parse the corpus once per source seal; workers query indexes instead of reopening all lesson files.
Precompute representative samples and screenshots in deterministic batches; retain only failures plus a small approved evidence sample.
Warm production routes once per route family before viewport/theme captures.
Reuse one dependency install and one production build per immutable source seal.
Regenerate only invalidated indexes after a bounded batch; run a full refresh at wave gates.
