# Premium Experience Rebuild Plan

## Operating rule

The rebuild proceeds in dependency order. A later wave does not begin while an earlier shared architecture defect remains open. Curriculum mathematics changes require row-level audit evidence and separate review; shell work must not alter answers, explanations, grading, or skill sequencing.

## Wave A — mathematics-first lesson player (implemented in S226)

Objective: make the active mathematical object the primary visual and semantic focus.

- Consolidate lesson title and progress into the existing sticky header.
- Remove repeated waypoint and “trail clearing” labels from active work.
- Remove active-work terrain decoration while preserving the completion summit.
- Compress resume state and delete ornamental action-dock prose.
- Preserve 44 px controls, keyboard order, narration, predictions, grading, adaptive feedback, XP, and completion behavior.
- Verify at 390, 768, and 1440 px in light/dark themes, plus keyboard, reduced motion, forced colors, overflow, and target sizes.

Exit gate: the mathematical prompt/model begins materially higher in the viewport; exactly one visible lesson heading remains; no active-work trail atmosphere, waypoint card, or clearing label is rendered; all current-source gates pass or have a documented pre-existing exception.

## Wave B — canonical math typesetting

Use `MATH_TYPESETTING_AUDIT.csv` to convert the highest-risk B/C rows first. Provide one accessible KaTeX + MathML path for prose, prompts, options, feedback, figures, and summaries. Preserve ordinary text where mathematical rendering adds no value. Validate line breaking, zoom, copy/paste, screen-reader output, and dark theme.

## Wave C — MCQ distractor remediation

Use `MCQ_DISTRACTOR_AUDIT.csv`. Fix FAIL rows by removing length/punctuation/notation leakage and grounding every distractor in a misconception, `commonError`, or documented rationale. Do not convert judgment tasks merely to reduce an MCQ count.

## Wave D — prediction rationalization

Use `PREDICTION_GATE_AUDIT.csv`. Remove predictions that duplicate the graded task or lack a direct causal consequence; reframe incomplete causal predictions; retain only informative, ungraded prediction → action → reveal loops.

## Wave E — visual rebuild and scaling

Use `VISUAL_REBUILD_QUEUE.csv`. Start with P0/P1 reusable figures, validating 390/768/1440 light/dark before broad rollout. Preserve mathematical relationships, labels, meaningful alternatives, and vector clarity.

## Wave F — direct manipulation

Use `DIRECT_MANIPULATION_AUDIT.csv`. Prototype DIRECT rows first, retain sliders only as accessible precision fallbacks where HYBRID is warranted, and keep honest single-variable sliders. Every direct handle needs keyboard parity, visible focus, 44 px target geometry, and deterministic state feedback.

## Wave G — engine polish

Use `PREMIUM_ENGINE_PRIORITY.csv`, sorted by learner harm × frequency × visibility × strategic importance. Repair high-use REDESIGN rows before adding new engines. A polished engine must expose direct mathematical state, visible consequences, specific error diagnosis, touch/keyboard parity, mobile fit, and reduced-motion behavior.

## Wave H — grade-aware maturity

Tune density, language, spacing, and scaffolding by grade band without fragmenting the component system. Preserve one engine contract with age-appropriate presentation layers.

## Wave I — responsive, accessibility, and performance hardening

Run the full surface matrix at 390/768/1440 light/dark. Add screen-reader, forced-colors, zoom/reflow, target-size, overflow, hydration, bundle, and security checks. Fix systemic failures in shared components.

## Wave J — final comparison and closure

Repeat the baseline captures and compare like-for-like states. Publish the adversarial QA, execution report, closure ledger, deployment identity, and sealed session archive only when the current-source branch and verified build agree.
