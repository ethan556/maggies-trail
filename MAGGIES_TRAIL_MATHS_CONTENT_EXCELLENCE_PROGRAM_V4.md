## Executive decision

Maggie's Trail is no longer in a broad build-out phase. It has a 129-course, 1,701-lesson curriculum; a functioning learner world; mature mathematical rendering and interaction infrastructure; and extensive safety gates. The programme now optimizes the system through evidence-backed root-cause work.

The governing rule is simple:

> Learner-visible mathematical truth, accessibility, and reasoning quality outrank coverage counts, visual decoration, historical plans, and delivery speed.

The World Atlas is therefore an enabling workstream inside content excellence—not a parallel rebuild. It may orient learners toward sound next actions, but it must never fabricate progress, prerequisites, connections, or mastery.

## Programme objectives

1. Ensure every learner-visible mathematical claim, answer, representation, and feedback state is truthful and mutually consistent.
2. Give each mathematical idea an appropriate, evidence-reviewed representation: visual, interactive, symbolic/table/derivation, safely withheld, or replacement asset required.
3. Preserve direct manipulation, immediate feedback, accessible alternatives, and grade-appropriate language across authored, remedial, challenge, and generated paths.
4. Use the World Atlas to improve orientation, review, and return paths without turning lessons into a game layer.
5. Maintain a source-sealed, reproducible evidence chain from curriculum source through reports, queue, review authority, planning, and cache.
6. Prove learner and release quality through deterministic gates, browser checks, independent review, and representative learner studies.

## Workstreams and acceptance criteria

### A. Source truth, batch processing, and precaching

**Purpose:** give every worker a current, immutable input packet and prevent stale reports from driving edits.

- Freeze source writes at coherent boundaries before full derived rebuilds.
- Build from content hashes, not timestamps or a clean Git tree assumption.
- Produce task packets with allowed files, source projection hash, evidence inputs, expected gates, stop rules, and independent-assessment requirements.
- Parse the curriculum once per source seal. Workers query cached curriculum, figure, generator, duplicate, presentation, and task indexes instead of repeatedly scanning the full corpus.
- Invalidate narrowly: lesson edit → its lesson/step records; generator edit → all generator users/sample outputs; shared renderer/schema edit → all dependent placements and browser fixtures.
- Precache deterministic route families and reuse the production build only within one immutable source seal.
- Regenerate broad evidence at wave gates, not after every individual line edit.

**Acceptance:** two-run deterministic output where supported; source-seal parity through cache; no generator may silently write learner source during an audit/check run.

### B. Mathematical, figure, and interaction truth

**Purpose:** eliminate misleading instructional states.

- Text, visible model, ARIA description, evaluator, feedback, and generated variant must agree on values, operation, units, direction, and result.
- Number-line changes require direction arrows when a movement claim is made; labels must remain visible at narrow widths and zoom.
- Concrete decimal values use numerals, for example `0.5`, unless a task explicitly teaches how to read the numeral aloud.
- Shared graph, chart, histogram, boxplot, table, SVG/KaTeX, and widget changes must prove behavior across every consumer, not only one lesson.
- If an exact representation cannot be proved, withhold it and record replacement debt. Never reattach an attractive but incorrect fixed exemplar.

**Acceptance:** zero unsafe rendered numeric/operation/direction conflicts; evaluator and accessible-output parity; collision/clipping gates pass at required viewports.

### C. Semantic representation assurance

**Purpose:** replace raw visual counts with an auditable learning-representation decision.

Each learner-visible concept or interactive surface receives one independently reviewed outcome:

1. `EXACT_VISUAL`
2. `EXACT_INTERACTIVE`
3. `SYMBOLIC_TABLE_DERIVATION`
4. `SAFE_WITHHELD`
5. `REPLACEMENT_ASSET_REQUIRED`

Authoring records contain only a compact representation kind, controlled rationale, and applicable asset/widget reference. Generated evidence determines rendering, numeric parity, safety, viewport, and accessibility state. No authored boolean may self-approve alignment, safety, or sufficiency.

**Acceptance:** exactly one current decision per in-scope surface; source changes stale it; raw no-figure state remains unclassified until independent review; replacement debt groups by reusable mathematical model.

### D. Accessible learner experience

**Purpose:** ensure every learner can find, operate, interpret, and recover from learning tasks.

- Strong visible focus, skip navigation, correct modal focus containment/return, and keyboard-equivalent direct manipulation.
- Non-colour state cues, coherent status messages, and visible/ARIA agreement.
- `prefers-reduced-motion` behavior in addition to in-app motion preferences.
- Reading preferences include prompt text without damaging KaTeX, tables, SVG labels, or direct controls.
- Browser verification across phone, desktop, keyboard, reduced motion, high contrast/forced colours where applicable, and physical 200% zoom.

**Acceptance:** representative routes complete without a pointer; required labels and focus remain visible; no focus escape or background interaction from a modal.

### E. Curriculum, generator, and course-family excellence

**Purpose:** repair root causes while protecting stable learner and grading contracts.

- Prefer shared primitive, generator, formatter, or state fixes before downstream lesson patches.
- Use course-family packets for specific, source-verifiable causes; preserve stable IDs, evaluator payloads, correct-option identity, and misconception feedback unless the packet explicitly re-specifies them.
- Review authoring duplication, MCQ integrity, grade language, progression, remedials, and challenge transfer independently from mechanical source closure.
- Generate variants from one compatible state model; do not patch a sampled output by hand.

**Acceptance:** all relevant authored/generated/remedial paths pass targeted and cross-family gates; independent assessment is current-hash bound; no closure rests solely on implementor assertion.

### F. Evidence-backed World Atlas

**Purpose:** make the existing world useful to learning rather than decorative.

- Preserve mathematics-first player containment; world UI never competes with active reasoning.
- Keep progress, review, landmark state, return paths, and instruments derived from existing learner evidence.
- Add a cross-course trail only after the prerequisite or transfer relationship has a traceable source.
- Preserve action equivalence across Minimal, Guided, and Immersive modes and maintain accessible catalogue/list alternatives to maps.

**Acceptance:** each displayed connection, unlock, or recommendation has a data source and accessible explanation; no fictional `carried` state or unsupported mastery claim.

## Concurrent execution topology

Use available workers aggressively, but never race shared source-of-truth files.

| Lane | May run concurrently | Must be serialized |
| --- | --- | --- |
| Independent audit | Source scans, inventories, reviewer candidates, browser evidence | Must not edit the source packet it will certify. |
| Bounded implementation | Disjoint lesson-family files and isolated tests/reports | One owner per course/source set. |
| Shared primitive implementation | A single renderer, widget, schema, evaluation, or Atlas hot-file packet | One hotspot owner; all consumers retested before handoff. |
| Derived evidence | Read-only feasibility checks may run in parallel | Final writers run serially after source freeze: alignment → numeric claims/parity → queue/cards → planning → cache. |
| Browser verification | Route-major batches reuse warm builds and state | Cap to machine capacity; do not run alongside a full build or full generator sweep. |

### Batch sizes

- Shared primitive/root cause: one hot-file family at a time, then an exhaustive consumer test.
- Authored course repair: 10–30 learner surfaces per packet, or one complete small course.
- Illustration/representation repair: 25–50 placements only when they share a proven primitive/state family.
- Choice/progression review: 20–50 related items grouped by misconception or job family.
- High-use generator assurance: 5–10 related families per batch; at least 100 deterministic outputs, 500 for high-risk/high-reach families, exhaustive where practical.
- Independent assessment: one completed source packet per assessor, with current-hash and stale-candidate rejection.

## Precache policy

The V4 cache is an accelerator, not curriculum authority.

- Cache keys include source projection hashes, dependency lock hash, extractor version, runtime version, and deliberate exclusions.
- Cache task packets, curriculum graph, figure/renderer graph, generator-user graph, visual/duplicate/presentation indexes, and deterministic sample manifests.
- Cache invalidation follows the narrowest true dependency boundary.
- The manifest writes last and must report a matching source seal.
- Cache outputs do not replace lesson JSON, evaluator source, review authority, or independent assessment.

## Release gates

A release affecting learning content, shared representation, or the World Atlas requires:

- current source-sealed derived artifacts and cache;
- content schema, pedagogy, CML, TypeScript, scoped lint, and required integration gates;
- zero unsafe figure/text/numeric/direction conflicts;
- semantic-representation contract and independent decision validity for the scoped surfaces;
- browser checks at 390px, desktop, keyboard-only, reduced motion, and 200% zoom;
- visible/ARIA/evaluator/feedback parity;
- deterministic queue, review-card, portfolio, and cache verification; and
- targeted learner-route regression evidence.

## Explicitly out of scope until evidence supports it

- decorative world expansion, fictional trail connections, or reward loops;
- broad figure-attachment targets that reintroduce mismatched diagrams;
- audio, avatar art, and PWA/offline work used as substitutes for learning quality;
- treating automated review cards or historical plans as independent curriculum authority;
- concurrent writes to shared renderers, schemas, canonicalizers, evaluation engines, or derived ledgers.
