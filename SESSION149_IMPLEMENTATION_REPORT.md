# Session 149 implementation report

## Breakthrough

Created `geometricConstraintLab`, one declarative geometry-constraint engine spanning six lessons and 42 authored experiences. It does not collapse the lessons into a generic diagram or calculator: each task retains its own exact constraint system while sharing one truth, exploration, grading, narration, feedback, reveal, accessibility, CML, and seeded-generation layer.

## Shared mathematical state

The engine supports six exact task families:

1. **Perimeter constraints** — total perimeter, known contribution, repeated unknown-side multiplicity, remaining length, and exact split.
2. **Coordinate composition** — coordinate-derived width and height, individual piece area, and signed add/subtract composition.
3. **Area scaling** — linear scale factor and its squared area consequence.
4. **Crossing angles** — vertical equality, adjacent supplementation, and full-turn consistency.
5. **AA similarity** — completed angle triples, exact angle-set comparison, similarity verdict, and scale factor when defined.
6. **Pythagorean area** — leg-square areas, their sum, hypotenuse-square identity, and exact square-root length.

## Eight required surfaces

1. Plain `ZodObject` schema; cross-field rules remain in `widgetIntegrityErrors`.
2. Task-specific accessible diagrams derived from the shared truth.
3. Grading and `canCheck` based only on truth-approved exploration keys.
4. Correct-answer and learner-answer narration.
5. Misconception and wrong-path extraction.
6. CML catalog, mesh, kernel, capability, and mastery routing.
7. Seeded generator wrappers plus an independent 27,648-case sweep.
8. Registration, samples, stage width, keyboard tests, and structural `gateOne` coverage.

## Failures found through execution and release review

- The schema declaration used compressed syntax that the registration compiler could not discover.
- `geometricConstraintLab` was initially absent from `REGISTERED_WIDGETS`.
- The first widget sample used obsolete field names and could not satisfy the actual schema.
- Mutation M27 created a valid non-similar AA state instead of the intended no-correct-answer defect; the mutation was corrected rather than the engine weakened.
- Historical Session 147 and 148 content proofs did not yet authorize the exact six Session 149 follow-through lesson paths.
- Session 148 source-transpile and failure-first evidence became stale after legitimate Session 149 additions; both were regenerated by their own compilers.
- The inherited package and freshness workflows ended at Session 148; Session 149 proofs are now mandatory during regeneration and clean extraction.
- `PRODUCT_STATE` embedded the local Git commit and therefore changed after `.git` was excluded from the archive; source-archive identity is now host-independent.
- Session 144 source-transpile/content reports were executed during extraction but absent from the global freshness list; they are now first-class freshness artifacts.
