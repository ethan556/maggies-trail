## 1. Trace — where each row type comes from

Read `scripts/audit/consolidate-pending-workload-s236.mjs` in full.

- **`QUESTION_DIVERSITY_AND_TRANSFER`** rows (`work_id = EXCELLENCE-<lessonId>`) come from
  `EXCELLENCE_BACKLOG_S126.csv`, unconditionally — every row in that CSV becomes a queue row (lines
  396–413; no status/disposition filter in the consolidator itself).
- `EXCELLENCE_BACKLOG_S126.csv` is itself a **generated** file
  (`scripts/audit/excellence-backlog-s126.mjs`, npm script `audit:excellence`), not hand-maintained.
  Its generator: (a) computes each lesson's live tier/dimension scores by shelling out to
  `scripts/flagship-tier.mjs`, (b) takes the K–8 Tier C/D lessons as the "live backlog", (c) for any
  such lesson **not** already in the hand-maintained policy file
  `scripts/audit/excellence-dispositions-s126.json`, derives a disposition via
  `repetitionDisposition()` — but **only** if the lesson's live `transfer` dimension is still exactly
  `0`; if `transfer !== 0` (i.e. a genuinely distinct challenge/transfer job now exists) that lesson
  returns `null`, is treated as `unresolvedPolicy`, and — critically — **the whole generator throws**
  (`fail("policy/live backlog drift...")`) unless a human has added a matching policy entry. So a
  fixed lesson closes in one of two ways: it climbs out of Tier C/D entirely (drops out of the "live
  backlog" silently), or it stays Tier C/D with `transfer !== 0` and *requires* a new,
  judgment-bearing entry in `excellence-dispositions-s126.json` (interactionIntent,
  representationRequired/Present, candidateDisposition, honestRestingTier, etc.) or the regenerator
  fails outright.
- `excellence-dispositions-s126.json` is the genuine hand-maintained adjudication artifact for this
  workstream (its own `source` field narrates prior sessions removing/adjudicating rows by hand,
  e.g. "S241 removed five stale WS-E rows after prediction scoring was corrected"). Its `records`
  array is currently **empty** — every currently-classified row is machine-derived via the S243
  `transfer === 0` rule, not hand-adjudicated.
- **`CLOSURE_LEDGER`** rows (`work_id = LEDGER-<CL-id>`) come directly from `CLOSURE_LEDGER.md`
  (consolidator lines 438–466): the consolidator regex-matches every `| CL-P0-… |` / `| CL-P1-… |`
  table row across the whole file, keeps the **last** occurrence per ID (later per-session update
  tables override earlier ones — this is how the file is meant to be amended), and queues it if that
  latest status cell still contains the substring `OPEN`. `CLOSURE_LEDGER.md` is fully hand-maintained
  prose/tables; there is no generator. This is the one row type this packet could legitimately edit
  in place, by appending a new dated session-update table in the file's own established format
  (exactly what S222–S236 already did repeatedly for the same IDs).

## 2. QUESTION_DIVERSITY_AND_TRANSFER — mechanism determined, closure BLOCKED this round

The legitimate closure mechanism is **rerunning `npm run audit:excellence`** (`node
scripts/audit/excellence-backlog-s126.mjs`). This is a live recomputation from current lesson source
via `flagship-tier.mjs` — not a hand-edit — and precedent confirms it is the intended mechanism: every
cited S263/S264/S267/S268/S274/S282 repair report ends with an explicit statement that it did **not**
touch the queue or disposition artifact (verbatim from `S263_COUNTING_TO_20_K_P0_REPAIR.md`: *"No
authoritative queue or disposition artifact was regenerated by this packet"*) and leaves that
regeneration to "the queue's own integration owner" (S318's own phrase). That is the role this packet
was asked to play.

**This task's own step 4 boundary — "Rerun `npm run audit:pending-workload` ONCE at the end… Do not
run other writers" — forecloses that mechanism for this round.** `audit:excellence` is a writer (it
regenerates `EXCELLENCE_BACKLOG_S126.{csv,json,md}` and, via `flagship-tier.mjs`, also
`FLAGSHIP_TIERS.md`), so running it here would violate the explicit "no other writers" instruction.
It also carries a real, unverified-by-me risk: if any of the 14 NOT_REPRODUCIBLE lessons is still
Tier C/D on the live scorer but now has `transfer !== 0`, the generator does not quietly drop the row —
it **throws and fails the whole script** unless a matching policy entry already exists. I cannot
determine which of the 14 lessons would land in that state without running the same forbidden tier
scorer, so I cannot respond to that risk correctly from this scope.

The two remaining fallback options in the task's own decision tree are both closed off:

- **Hand-editing the generated CSV directly** (deleting/marking the 14+1 rows in
  `EXCELLENCE_BACKLOG_S126.csv`) is explicitly forbidden ("NEVER just delete rows from a generated
  file") and would drift from the next real `audit:excellence` run anyway.
- **Appending entries to the hand-maintained adjudication file**
  (`scripts/audit/excellence-dispositions-s126.json`) is not honestly available either: a legal entry
  requires substantive judgment fields (`interactionIntent`, `representationRequired`,
  `representationPresent`, `candidateDisposition`, `honestRestingTier`, …) that the generator derives
  from the live tier/transfer computation I am blocked from running, and inventing them would be
  exactly the "decide an unplanned … pedagogical … question" the worker-prefix contract forbids.
  Fabricated entries would also risk becoming `stalePolicy` (crashing the next legitimate run) if the
  lesson has in fact already climbed out of Tier C/D.

**Result: QD row closure is BLOCKED this round by this packet's own scope, not by missing evidence.**
The evidence (`S318_QD_P0_IMPLEMENTATION.md`, plus the underlying S263/S264/S267/S268/S274/S282
repair reports it cites per row) already proves 14/15 rows are stale detector signals and the 15th
(`fa-02-02`) is fixed. Nothing in `EXCELLENCE_BACKLOG_S126.csv`, `EXCELLENCE_BACKLOG_S126.json`,
`EXCELLENCE_BACKLOG_S126.md`, `scripts/audit/excellence-dispositions-s126.json`, or
`scripts/audit/consolidate-pending-workload-s236.mjs` was modified by this packet.

**Recommended follow-up (out of this packet's scope):** an authorized packet should run `npm run
audit:excellence` followed by `npm run audit:pending-workload`, watch for the `unresolvedPolicy`
failure mode described above, and add any genuinely-required `excellence-dispositions-s126.json`
entries only for lessons that fail that way with a real live-tier record in hand.
