# S330 Progression Packet G8 — LESSON_PROGRESSION_AND_DUPLICATION

Scope: queue workstream `LESSON_PROGRESSION_AND_DUPLICATION` (generated by
`scripts/audit/consolidate-pending-workload-s236.mjs`, lines ~358-393), the 11 lessons assigned to
packet G8 across three courses: `long-division-g5` (g5l), `radical-functions` (re, high school),
`shapes-measure-g1` (smg1, Grade 1).

**Method.** The detector was reproduced verbatim (digit-strip to `#`, collapse whitespace, cluster by
identical normalized widget-prompt template within one lesson) as a standalone script and run against
every lesson's live JSON, both to confirm the queue's flagged step IDs and to find each flagged step's
actual colliding sibling(s). Every lesson was then read in full. Judgment: KEEP where the collision is
defensible fluency/retrieval practice or where the two steps' authored body/hints/concept-card text
already signals a genuinely different sub-case or misconception; REDESIGN where a later step (usually
the challenge) poses the identical question job as an earlier step with no distinguishing content.

Result: **10 lessons KEPT, 1 lesson REDESIGNED** (one step: `smg1-04-01/ch1`).

## The `shapes-measure-g1` ch4 cluster (Grade 1 telling-time, 3 consecutive lessons)

All three lessons use the `clockSet` widget with the single sentence template "Set the clock to show
#:#." for nearly every graded/interactive step — structurally unavoidable at this grade for this skill
(there is no other age-appropriate way to phrase "set the clock to hour/half-hour X" many times over).
Each lesson was judged independently and landed on a genuinely different outcome, avoiding a
one-size-fits-all treatment of the three:

### smg1-04-01 — Telling Time on the Hour

Flagged: `i2`, `i3`, `k2`, `ch1` (all vs. anchor `k1`, template "Set the clock to show #:#.").
- `i2` (10:00) and `k2` (5:00): ordinary G1 fluency reps of the plain on-the-hour skill at different
  clock positions — legitimate, kept.
- `i3` (12:00): the noon/midnight edge case where BOTH hands point to 12 — explicitly taught by its own
  preceding concept card `c3` ("that's the one time both hands overlap on the hour"). Legitimate, kept.
- `ch1` (11:00) was the genuine miss: the challenge posed the identical `clockSet` construct action as
  `k1`/`i2`/`k2` with no distinguishing content of its own — generic body ("Watch the hands carefully"),
  and the near-12 idea gestured at in its old `hourFeedback` ("not 12:11") was never actually tested,
  since `clockSet` only grades final hand placement, not a chosen wrong reading.

**Decision: REDESIGNED `ch1`.** Old job: construct (drag hands) a clock reading 11:00 — mechanically
identical to `k1`/`i2`/`k2`. New job: **read/identify** — given a hand position described in words,
select the correct time from four options, with the near-12 trap made real:
- Prompt: "The hour hand points to 11 and the minute hand points to 12. What time is it?"
- Correct: **11:00**.
- Traps: **12:00** (rounds the near-boundary hour hand up to the next number — the exact misconception
  the old feedback only gestured at without testing), **12:11** (swaps which hand supplies the hour vs.
  the ":00" reading), **10:00** (off-by-one the other direction).
- Math check: hour hand at 11 + minute hand at 12 (exactly on the hour) = **11:00**, unambiguous.
  12:00/12:11/10:00 are all distinct from 11:00 and from each other.
- Widget changed `clockSet` → `mcq` (matching the exact mcq-clock-reading shape already used by this
  lesson's own remedial check, so no new widget pattern was invented). No `variant` field existed on
  `ch1` before or after this edit — nothing to remove, no generator file touched.
- `cml` block updated to match: `stage` "construct" → "retrieve"; `representations`/`translationFrom`/
  `translationTo` "concrete"→"symbolic" replaced with "language"→"symbolic" (reading a word description,
  not manipulating a model); `actionGoal`, `invariants`, `misconceptions`, and `counterfactualPrompt`
  rewritten to describe the new read/identify task instead of the old manipulate task.
- Verification: `node -e "JSON.parse(...)"` passed; the detector-replica script re-run on the edited
  file shows `ch1` no longer appears in any cluster (remaining cluster is `[k1, i2, i3, k2]`, all
  judged legitimate above); `npx vitest run src/lib/session274.shapesMeasureG1Course.test.ts` passed
  (3/3) — this file schema-validates every widget in the course via `WidgetSpec.parse` +
  `widgetIntegrityErrors`, and specifically asserts every `mcq` has exactly one correct option that
  evaluates correct. Confirmed via `content/mastery/direct-manipulation-map.json` and
  `mastery-arc-contracts.json` that this objective's canonical direct-manipulation reference points at
  `smg1-04-01/i1` (untouched), not `ch1`, so the edit does not disturb those catalogs.

### smg1-04-03 — On the Hour or Half Past?

Flagged: `k1`, `i2`, `i3`, `k2`, `k3`, `ch1` (all vs. anchor `i1`, same template).
- This lesson's entire purpose is discrimination fluency: it deliberately **alternates** on-the-hour and
  half-past targets across every single step (`i1`=4:00, `k1`=6:30, `i2`=8:00, `i3`=2:30, `k2`=1:00,
  `k3`=10:30, `ch1`=12:00) specifically to force the "check the minute hand first" strategy taught by
  `c1`/`c2` to generalize across both cases and many hours. The identical sentence template across
  every step is not an authoring accident — it is the mechanism by which discrimination is tested (any
  other phrasing would leak which case a given item belongs to). `ch1` (12:00) is the deliberate
  hardest case: the one configuration where BOTH hands point to the same number, explicitly flagged in
  its own body ("Both types in a row") and hints ("Check the minute hand first... The hour hand is also
  at 12: 12:00").

**Decision: KEPT — no edit.**
